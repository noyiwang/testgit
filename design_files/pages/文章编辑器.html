引言

在 Go 语言中，并发编程是核心特性之一。本文将从 Goroutine 的基本概念出发，深入探讨 Go 并发模型的设计哲学与实战技巧。

Goroutine 基础

Goroutine 是 Go 语言的轻量级线程，由 Go 运行时管理。与操作系统线程相比，Goroutine 的创建成本极低，初始栈大小仅为 2KB。

func main() {
    go func() {
        fmt.Println("Hello from goroutine")
    }()

    fmt.Println("Hello from main")
    time.Sleep(time.Second)
}

并发不是并行。并发是同时处理很多事情，而并行是同时做很多事情。

— Rob Pike

Channel 通信

Channel 是 Go 并发模型的核心通信机制，遵循 "不要通过共享内存来通信，而应该通过通信来共享内存" 的设计哲学。

ch := make(chan string, 1)

go func() {
    ch <- "数据已就绪"
}()

msg := <-ch
fmt.Println(msg)

并发模式对比

特性 Goroutine OS Thread
创建成本 ~2KB ~1MB
切换开销 ~200ns ~1μs
调度方式 协作式 (GMP) 抢占式
内存占用 极低 较高

实战建议

1. 控制并发数量：使用 semaphore 模式限制 Goroutine 数量

2. 优雅关闭：利用 context.Context 实现超时与取消

3. 错误处理：使用 errgroup 管理并发错误

4. 资源泄露：确保 Channel 和 Goroutine 正确关闭
